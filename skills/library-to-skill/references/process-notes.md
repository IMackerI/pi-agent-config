# Process Notes

These are small process choices that make doc-to-skill work smoother.

## Choose the niche early

A Telegram example made this obvious: several existing skills already covered adjacent niches, but not the exact one we wanted.

Common niches:

- raw API knowledge
- framework-specific implementation
- workflow automation
- product or architecture guidance

Choosing the niche early reduces duplicate research and gives the skill a clearer trigger surface.

## Prefer a temporary first pass

A narrow temporary skill is often the fastest useful artifact. It can be good enough with:

- one canonical source
- a few high-value sections
- a short skill body
- one workflow reference
- one source map

That first version often reveals what is still missing more clearly than more up-front research.

## Look for reusable patterns

Good distilled notes often come from questions like:

- what are the recurring decisions?
- what loop does most work revolve around?
- what options repeat across many methods?
- which constraints or limits are easy to forget?
- which edge cases deserve a direct link back to the docs?

## Single-page docs are often enough

When docs live on one large page, the process can stay simple:

- extract the main content area
- pull a small set of named sections
- preserve the section anchors
- turn those into a workflow note plus a source map

## Compare neighboring skills

Existing skills are useful not only as substitutes but as positioning clues. They quickly show whether the missing value is likely to be:

- better source grounding
- a narrower framework focus
- a cleaner reference structure
- a different audience or abstraction level
